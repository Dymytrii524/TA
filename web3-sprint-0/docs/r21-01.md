# R21-01: verified transaction and event promotion

Existing submitted/included transactions now promote atomically after the wallet
reconciler verifies finalized canonical receipts and logs. Exact finalized replay
does not UPDATE protected rows. Height/hash/status conflicts halt; pre-finality
re-inclusion requires proof the old block is no longer canonical and retains the
old observation in append-only migration 007. Existing non-final events promote
only when their complete payload matches.

`node tests/finality.test.mjs` exercises PGlite; set the dedicated local
`WEB3_TEST_DATABASE_URL` to run two real PostgreSQL sessions. CI uses PostgreSQL 18.
The wallet EVM suite now pre-registers real included settlement and submitted
withdrawal transactions before reconciliation.

Chain truth does not mark API intents confirmed: registration/matching of general
deal intents remains a separate integration boundary. No blind confirmation of
an intent based on a client-supplied hash is introduced. No signing, broadcasting,
external deployment, schema finality-guard removal or merge.

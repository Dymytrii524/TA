# R21-04: causal mapping evidence, not wall-clock inference

The SQL/chain timestamp comparison has been removed, not rounded or relaxed.
DB milliseconds and block seconds cannot establish which operation happened first.

## New mappings

Apply migration 009 after 008. The trusted server must call and await
`recordMappingPreflight(db, rpc, dealId)` after immutable terms commit and before
returning create calldata for signing. It reads the current canonical block,
checks chain/code and an absent on-chain escrow, and appends exact scoped evidence.
It accepts no caller-supplied block, time or claimed observation. It signs and
broadcasts nothing. Reconciliation checks the evidence anchor is canonical,
the escrow was absent there, and funding occurred in a strictly later block.

This is a server-observed proof under the existing trusted, synchronized RPC and
privileged DB-writer boundary, not a cryptographic attestation of a SQL commit.
Only the trusted prepare service may insert evidence; no public endpoint exists,
PUBLIC has no grants, and production role grants must be verified separately.
Do not point it at an untrusted/stale RPC. A reorg of the proof anchor fails closed.

Terms without this evidence remain unattributed unless approved explicitly.
This is intentional: old timestamps, including timestamps far before funding,
are not grandfathering evidence. General create HTTP integration remains an
explicit production gate; this patch provides the executable helper and tests,
not a claim that the missing create worker has been deployed.

## Historical continuity

On first V2 activation, V1 lots can provisionally supply their existing exact
escrow/deal attribution. All historical snapshots must then pass canonical-anchor
verification and full deterministic replay equality before any V2 publication.
Corrupt V1 history still refuses atomically; old snapshots are never rewritten.
The resulting immutable V2 classification persists only for the same funding
event and deal. Previously published UNATTRIBUTED classifications still require
the existing dual approval, even when evidence is later found.

An empty V1 ledger supplies no attribution for unrecorded escrows. Such historical
terms need explicit offline approval, not automatic migration. No payout policy,
48-hour review rule, funds movement or chain contract changes are introduced.

## Regressions

`tests/mapping-evidence.test.mjs` runs real Anvil + PGlite and PostgreSQL:
same-second freeze/funding, +/-120-second clock skew, canonical proof validation,
append-only/scope guards, real unchanged V1 runtime migration, corrupt-history
atomic refusal, post-funding proof refusal, missing evidence and RPC failure.
Existing subset tests retain genuine freeze-after-payout and dual approval checks.
The fixture no longer advances time by two seconds to hide the clock boundary.

CI uses a separate local Anvil on 8546 started 600 seconds in the past; scenarios
revert only their own local snapshots. No deployment or external RPC is used.

# R21-03: fail-closed HTTP error boundary

Explicit DomainError instances retain 401/403/404/405/409/413/422. Reconciliation
always crosses a separate error boundary: arbitrary downstream `status` fields,
DB/RPC messages and stack traces are not trusted HTTP responses.

All reconciliation failures return 503, title `Reconciliation unavailable`,
code `RECONCILIATION_UNAVAILABLE` and a generated correlation_id. Audit entries
contain only the correlation and allowlisted reason, never raw SQL, credentials,
RPC URL or arbitrary exception text. Logger failure cannot change the response.

The handler never returns a cached successful balance or prepares an intent after
a failed refresh. Verified UNATTRIBUTED data remains success, not an error.
Run `node tests/http-errors.test.mjs` with local Anvil for actual HTTP and complete
OpenAPI schema validation, including both claims and intents.

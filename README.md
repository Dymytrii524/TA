# Trans-Atlas

Дизайн-концепт біржі вантажоперевезень (натхненний trans-atlas.net) — односторінковий застосунок з робочою навігацією, пошуком вантажів/транспорту, ринком техніки, новинами, входом/реєстрацією та інтерфейсом на 4 мовах (UA/EN/PL/DE).

## Запуск

Відкрити `index.html` у браузері — окремий сервер не потрібен для основного сайту, увесь код (HTML/CSS/JS) знаходиться в одному файлі.

### Навмисні копії

Однаковий вміст за різними шляхами лишається лише там, де його тримає прогін, тому копія не може тихо відстати:

| Робочий файл | Копія | Хто стежить |
|---|---|---|
| `.github/workflows/contract.yml` | `ci/github-actions-contract.yml` | R14 у `ci/check_ruleset.py` |
| `.github/workflows/backend.yml` | `ci/backend-contract.yml`, `docs/ci-backend-contract-workflow.yml` | R14, D12 |
| `.github/workflows/source-probe.yml` | `ci/source-probe.yml` | R14 |
| `ci/check_ruleset.py` | `docs/ci-check-ruleset-proposed.py` | D12 у `ci/check_doc_counts.py` |
| `ci/ruleset-contract.json` | `docs/ci-ruleset-contract-proposed.json` | D12 |
| `sprint-0-backend/ТЗ-бекенд-Спринт-0.md` | `docs/backend-sprint0-spec.md` | D12 |
| `sprint-0-backend/ТЗ-верифікація-контрагентів.md` | `docs/verification-spec.md` | D12 |

Правити слід робочий файл, а копію оновлювати тим самим комітом.

`i18n/currencies.json` і `sprint-0-backend/seed/currencies.json` не дублікати. Перший описує 9 валют із ролями (база, курс, комісія, аналітика) для контрактних сценаріїв, а другий — 32 валюти із символами й позицією знака для заповнення БД; перший список повністю входить у другий.

### Коли запускаються прогони

У pull request прогінні job-и конвеєра «Контракт» виконують кроки лише тоді, коли змінено файл із їхнього фільтра змін. Фільтр мусить містити кожен файл, який читає прогін, інакше pull request, що змінює лише такий файл, отримує зелену перевірку без прогону. Це стереже `ci/check_change_filters.py` (F1–F4): він виводить множину читаних файлів зі скриптів кожного job-а і звіряє її з фільтрами GitHub і GitLab. У `main` фільтр не діє, і всі кроки виконуються завжди.

## Сервіси (`server/`)

Розділ "Сервіси" підключений до окремого локального бекенду:
- **Погода** — вкладка Авто: Open-Meteo прогноз + активні штормові попередження MeteoAlarm накладені на нього за країною. Вкладка Авіа: METAR/TAF з AviationWeather.gov за ICAO-кодом аеропорту, з готовою категорією льотних умов (VFR/MVFR/IFR/LIFR). Українські аеропорти чесно показують "немає даних" (закритий повітряний простір), а не помилку.
- **Довідник** — структурований каталог 8 офіційних джерел/агрегаторів (`server/data/directory.json`), з фільтрами за видом транспорту, регіоном і пошуком.
- **Кордони** — живі дані з двох джерел одночасно: ДПСУ (251 пункт пропуску, черги вантажівок/легкових авто з боку України) та granica.gov.pl (9 пунктів UA-PL, розрахунковий час очікування з боку Польщі). Обидва джерела незалежні — якщо одне недоступне, показуються дані з іншого (`partial: true` у відповіді API).
- **Питання і відповіді (Q&A)** — база знань (Wiki, `server/data/wiki.json`) і готові чек-листи (Outputs, `server/data/outputs.json`) з логістики (CMR, Інкотермс, TIR, ADR, митний транзит ЄС тощо), плюс AI-чат. Пошук по базі — локальний keyword-retrieval (`server/services/qaRetrieval.js`), без векторної бази. AI-відповідь генерується через Anthropic Claude API лише на основі знайдених статей — модель отримує ТІЛЬКИ ці матеріали в контексті і явну інструкцію чесно казати "даних недостатньо", якщо базі бракує інформації, а не вигадувати факти. Без `ANTHROPIC_API_KEY` ендпоінт `/api/qa/ask` чесно повертає знайдені статті без AI-тексту, а не фейкову відповідь (див. `.env.example`).

Вкладки "Азія" (Кордони) і "Залізниця"/"Море" (Погода, Кордони) чесно показують, що відповідні джерела (CAREC BCP Monitor, Copernicus Marine) ще не підключені — жодних вигаданих даних.

Запуск бекенду (Node.js 18+, без `npm install` — нуль зовнішніх залежностей):
```
node server/index.js
```
Сайт (`index.html`) сам виявляє, чи бекенд запущений на `http://localhost:8787` — якщо ні, вкладка "Погода" чесно показує повідомлення про це, а не помилку чи фейкові дані.

Тести конекторів (без мережі; додайте `--live`, щоб один раз реально звернутися до джерела):
```
for f in server/tests/*.test.js; do node "$f"; done
```

Деталі джерел даних, TTL, ліцензії — `SOURCES.md`. Змінні середовища — `.env.example`.

## Важливо

- Головний сайт — фронтенд-демонстрація без бекенду: вхід/реєстрація та заявки зберігаються локально в браузері (`localStorage`), а не в реальній базі даних.
- Контактні дані (телефони, email, адреси офісів) — приклади-заглушки для демонстрації, перед публічним запуском їх потрібно замінити на реальні.
- `server/` — робочий локальний бекенд-зріз (не розгорнутий і не production): GitHub Pages, куди веде цей репозиторій, обслуговує лише статичні файли й не може запускати Node/шедулер/кеш. Реальний деплой бекенду — окреме рішення про хостинг, ще не прийняте.

## Зображення у банері (`images/`)

Ілюстрації видів транспорту — переважно AI-згенеровані концептуальні рендери (не фотографії реальних машин/суден/потягів), про що вказано у футері сайту. Виняток — банер "Дрони" (реальне фото, не рендер, див. нижче):

- `banner-auto.jpg` — футуристична фура на сонячних панелях
- `banner-rail.jpg` — швидкісні потяги (кадр з колажу)
- `banner-sea.jpg` — контейнерний термінал і суховантаж (кадр з колажу)
- `banner-air.jpg` — вантажні літаки в аеропорту (кадр з колажу)
- `banner-multi.jpg` — мультимодальний термінал: потяги, фури, контейнери (кадр з колажу)
- `banner-drone.jpg` — доставка дроном біля приватного будинку (надане користувачем фото, не AI-рендер — обрізане й змінене до 700×417 під розмір інших банерних плиток)

Перед публічним запуском рекомендується замінити їх на реальні фірмові фотографії.

# test-data — тестові заявки біржі

Синтетичний набір **7120 заявок** для перевірки пошуку, фільтрів, пагінації, таблиць потоків і рейтингу на реальному обсязі даних.

## Структура

| Файл | Що містить |
|---|---|
| `listings-<continent>.json` | агрегований набір по континенту (6 файлів) — **саме ці файли підключає `index.html`** |
| `listings-<continent>-<mode>.json` | той самий набір, розбитий по видах транспорту (36 файлів) — для точкових перевірок |
| `summary.json` | зведення: кількості, діапазон `id`, перелік файлів |
| `generate.py` | генератор набору (детермінований, `random.seed`) |

Континенти: `europe`, `asia`, `africa`, `north-america`, `south-america`, `oceania`.
Види транспорту: `auto`, `rail`, `sea`, `air`, `drone`, `multi`.

## Як це підключено до сайту

`index.html` після першого рендера викликає `loadExternalListings()`, який паралельно тягне 6 континентальних файлів і додає їх у той самий масив `LISTINGS`. Тому фільтри (`filteredListings`), пагінація «Показати ще» (`PAGE_SIZE` / `state.resultsShown`), рейтинг, статистика та таблиці потоків по країнах працюють з набором без окремої гілки коду.

- `id` заявок з `test-data` починаються з **100001**, вшитий демо-набір займає `1..3653` — колізій немає, а `mergeExternalListings()` додатково перевіряє `id`, щоб повторне завантаження не дублювало рядки.
- Якщо файли недоступні (офлайн, 404 або відкриття як `file://`), сторінка не падає: залишається вшитий демо-набір, а стан набору честно позначається в блоці результатів (`[data-feed-status]`) — без вигаданих чисел.
- Статус набору й лічильники доступні для QA з консолі: `TA_DEBUG.feed`, `TA_DEBUG.listings.length`, `TA_DEBUG.filtered("cargo").length`.

## Сумісність з моделлю даних

- `from` / `to` — **лише `id` з `CITIES`** в `index.html`, інакше фільтри «Звідки/Куди» не змогли б вибрати заявку, а `cityCountry()` не дав би країну для таблиць потоків і прапорців.
- `cargo` — лише `id` з `CARGO_TYPES`; `currency` — лише коди з `CURRENCIES` (включно з `USDC`/`USDT`/`EURC`).
- `mode: "multi"` має `components` (наприклад `["sea","auto"]`) — працює з фільтром складових мультимодального маршруту.
- `mode: "drone"` має `weightUnit`, `rangeKm`, `maxPayloadKg`, `droneType`, `flightPermit` — узгоджено з `schemas/post-drone.schema.json`.
- Морські заявки йдуть між портами, авіа — між авіахабами, решта — між усіма містами континенту; близько чверті маршрутів внутрішні (одна країна), решта міжнародні, щоб і `borderScope=domestic`, і `international` мали дані.

## Примітка

Дані синтетичні. Маршрути побудовані на реальних містах, портах і авіахабах, ваги/обʼєми/ставки згенеровані в реалістичних для кожного виду транспорту діапазонах. Це не комерційна інформація і не реальні пропозиції перевізників.
